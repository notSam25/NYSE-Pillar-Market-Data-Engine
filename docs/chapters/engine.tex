\section{Engine}

At its core, the engine should be a decoder and a source of heuristics. This
abstracts away much of the complexity involved in working with the data,
allowing the engine to relay decoded messages to a consumer as quickly as
possible.\\ Characteristics that the engine could or should track include
\texttt{msg/sec}, gap detection, and the specific messages decoded.\\ Features
that the engine could provide may include viewing specific messages and
replaying a selected interval of messages.\\ \vspace{5em}\\ The engine could
use a Parse $\rightarrow$ Model $\rightarrow$ View structure, where parsing
first will dispatch to a schema chosen by the consumer. Parsing will start with
looking at the datamodel defined by the schema then according to the message it
receives, direct execution to the model function for that message. The model
function has the job of doing any validation or post-processing of the data
before then sending it off into the view function for that message. This
structure allows for seperation of concern between each function.
